# ADR 0014: ORM

- Status: Accepted
- Date: 2026-10-26

## Context

The plan asks for an optional ORM built on the query builder, with explicit eager loading, mass-assignment protection, casts, safe serialization, no surprise queries during serialization, and no accidental N+1 behind relation access. It also forbids hidden global state and static facades in the core. The owner asked for URLs that use public ids instead of database ids.

## Options

1. **Laravel-style Active Record** (`User::find(1)`, `$user->posts` lazy loads). Familiar, but it needs a static connection resolver (global state), and lazy relation access is the classic source of hidden N+1 queries.
2. **Models plus an explicit `Orm` service** (`$orm->find(User::class, 1)`, relations only through `with()` / `load()`). Slightly more typing, but no global state, and every query is visible in the code.

## Decision

Option 2.

- **Models hold data only.** They never query. `Orm` (injected like any service) queries, saves and deletes.
- **Relations** (`belongsTo`, `hasOne`, `hasMany`, `belongsToMany`) are declared in `relations()` and loaded only with `ModelQuery::with()` or `Orm::load()`: one query per relation and nesting level, keys chunked at 500. **Reading an unloaded relation throws** `RelationNotLoadedException` with the exact fix, instead of running a query.
- **Mass assignment:** `fill()` accepts only `FILLABLE` attributes and **throws** for others. Silently ignoring them hides bugs and attacks. `forceFill()` / `set()` exist for trusted code.
- **Serialization** (`toArray()`, JSON) uses only loaded data, removes `HIDDEN` attributes and never queries.
- **Saving** inserts new models (ULID for `PUBLIC_ID`, timestamps) and updates only dirty columns. Saving an unchanged model runs no query.
- **Casts:** int, float, bool, string, datetime, date and json, validated in both directions; invalid values throw.
- **Public ids:** `findByPublicId()` returns null **without querying** for strings that are not valid ULIDs.
- **Route binding:** a handler parameter typed with a model resolves `{name}` by `PUBLIC_ID` (or by a positive integer primary key when there is none). Anything else, including malformed values, is a 404. This is done through a generic `RouteParameterResolver` hook in the router, so the ORM stays optional.
- **404 without HTTP coupling:** `ModelNotFoundException` implements the new core interface `HasHttpStatus`, which `HttpErrorResponder` understands. The ORM does not depend on the HTTP module.
- **Model constants are validated at runtime** (PHP 8.2 has no typed class constants).

## Consequences

- Code is a little longer than Laravel's (`$orm->query(User::class)` instead of `User::query()`), and every relation used must be listed in `with()`.
- Static analysis needs `@property` / `@property-read` annotations on models for magic attribute access; the docs recommend them.
- Not included yet: model events, soft deletes, polymorphic relations, pagination of models, and authorization (Phase 6). Route binding finds a record; the handler must still check that the user may access it.
- Update 2026-10-27: model events, soft deletes, scopes, `hasManyThrough` and morph relations were added within these rules; see [ADR 0039](0039-orm-soft-deletes-scopes-events-relations.md).

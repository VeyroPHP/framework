# ADR 0019: AI integration

- Status: Accepted
- Date: 2026-10-26

## Context

The owner asked for AI features as easy to add as in Laravel. The roadmap planned a separate `veyrophp/ai` package after 0.1.0.

## Decisions

- **One small, provider-neutral API** (`Ai`: `text`, `chat`, `json`, `stream`) with a `Provider` interface. Applications depend on `Ai`, not on a vendor SDK, so providers can be swapped or added.
- **Part of the framework, with optional dependencies** instead of a separate package: the module is small, and the vendor SDK is only a `suggest`. Nothing extra is installed for applications that do not use AI. This deviates from the roadmap's "separate package" plan; it can still be split out later without changing the API.
- **Anthropic driver through the official PHP SDK** (`anthropic-ai/sdk`), not hand-written HTTP: the SDK handles request formats, streaming, retries with back-off and `retry-after`, and API version changes.
  - Default model `claude-opus-5-5`; thinking left at the model default (adaptive); `effort` configurable.
  - Server-side refusal fallback on by default (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`); configurable off.
  - Structured output through `output_config.format` with a JSON schema; the framework decodes and checks the JSON.
  - `max_tokens` 16,000 for normal and 64,000 for streamed answers, so long answers do not time out.
- **Errors** become `AiException` with `isRetryable()` and `isRefusal()`; messages never include the key or the prompt.
- **Logs** contain provider, model, tokens, duration and stop reason, never prompts or answers.
- **Testing:** `FakeProvider` (queued answers, recorded requests). The Anthropic driver is tested with the real SDK and a fake PSR-18 transport, replaying the SDK's own captured streaming fixtures: no network, no key, no cost.

## Verified

19 framework tests, including request building (model, `max_tokens`, `system`, `output_config`, `fallbacks`, beta header), streaming from the SDK's `basic_text` and `refusal` fixtures, error mapping for 400/401/429/500/529 and network errors, and that the key never appears in error messages. The starter app's `ai:ask` command is tested with a fake.

**Not verified against the live API**: no API key was used, so no request reached Anthropic. The first real call should be made by the owner.

## Not done

- Drivers for other providers (OpenAI, Gemini); the interface allows them.
- Tool use (function calling), images and documents as input, embeddings, conversation storage.
- Cost tracking in money (only tokens are logged).
